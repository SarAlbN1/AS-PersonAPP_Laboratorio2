# Criterios para iniciar y cerrar trabajo

**Listo para iniciar.** El alcance, la persona responsable y los criterios son claros, las dependencias necesarias están resueltas y se identificaron los contratos afectados. [Backlog](../06-backlog/README.md).

**Listo para cerrar.** Los criterios se verificaron con evidencia real, se actualizaron las fuentes afectadas y el cambio quedó integrado según la [política de PR](../../../CONTRIBUTING.md#pull-requests-y-releases). El estado se actualiza donde el equipo gestione el trabajo. [Issues y milestones](issues-etiquetas-y-milestones.md).

Para cerrar cualquier HU se verifica la conservación de los siete módulos originales, sus responsabilidades y la arquitectura hexagonal conforme a las [reglas arquitectónicas](../02-arquitectura/reglas-arquitectonicas.md).

El proyecto solo puede cerrarse cuando HU-007, HU-033 y HU-034 y las demás historias obligatorias estén verificadas, HU-026 documente las 96 combinaciones básicas más paginación y consulta Persona–Teléfonos, HU-027 confirme la arquitectura, y README, Swagger, informe y tag correspondan al mismo commit final validado. Un bloqueo documentado no equivale a aceptación ni permite cerrar la entrega.
